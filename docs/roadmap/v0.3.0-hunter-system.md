# CdrBounty v0.3.0 — Hunter System

**Status:** Planned

## Goal

Create a persistent bounty-hunter career so hunting has progression, identity, unlocks, and measurable performance beyond raw money earned.

## Hunter License

Players may optionally be required to obtain a Hunter License before accepting advanced contracts.

Planned states:

- `UNLICENSED`
- `ACTIVE`
- `SUSPENDED`
- `REVOKED`

License rules should be configurable, including cost, permission bypass, and whether basic public contracts remain accessible without a license.

## Rank Progression

Initial conceptual ranks:

1. Rookie
2. Tracker
3. Hunter
4. Elite
5. Executioner
6. Legend

Rank names, thresholds, and rewards must be configuration-driven.

Potential requirements:

- Reputation XP.
- Contracts completed.
- Minimum success rate.
- Perfect hunts.
- Highest completed contract value.
- Specific achievement flags.

## Reputation

Reputation is separate from currency.

Positive sources may include:

- Contract completion.
- Difficult contract modifiers.
- Solo completion.
- Perfect-hunt objectives.
- Capturing high-value targets in later phases.

Negative sources may include:

- Abandonment.
- Contract failure.
- Confirmed collusion/abuse penalties.
- Administrative sanctions.

All reputation modifications require a reason code and audit history.

## Hunter Profile

Profile should expose:

- Current rank.
- Reputation and next threshold.
- Total contracts accepted/completed/failed/abandoned.
- Total bounty earned.
- Highest single payout.
- Current completion streak.
- Best streak.
- Unique targets captured/killed.
- Perfect hunts.
- Optional season statistics.

Commands:

- `/hunter`
- `/hunter profile [player]`
- `/hunter stats [player]`
- `/hunter contracts`
- `/hunter top`

## Contract Access

Contract requirements may reference:

- Minimum rank.
- Minimum reputation.
- License state.
- Maximum concurrent reservations.
- Cooldown after abandonment/failure.

The Contract Engine remains the authority; Hunter System provides eligibility data.

## Leaderboards

Planned categories:

- Reputation.
- Contracts completed.
- Total earnings.
- Highest single bounty.
- Completion streak.
- Perfect hunts.

Leaderboard queries must not perform expensive full-table scans on the main server thread.

## Seasons — Data Foundation Only

This phase should make statistics season-aware, but automated season rotation may remain disabled until later.

Store:

- Season identifier.
- Lifetime totals.
- Season totals.
- Historical season snapshots where configured.

## Permissions

Planned additions:

- `cdrbounty.hunter.use`
- `cdrbounty.hunter.license`
- `cdrbounty.hunter.profile`
- `cdrbounty.hunter.top`
- `cdrbounty.admin.hunter.modify`
- `cdrbounty.admin.hunter.suspend`

## Acceptance Criteria

v0.3.0 is complete when:

- License state persists and gates configured actions correctly.
- Reputation gains/losses are deterministic and audited.
- Configured rank thresholds promote/demote correctly.
- Rank-based contract access works through both GUI and commands.
- Hunter statistics survive restart and migration.
- Leaderboards return correct results under test data volume.
- Admin changes cannot silently corrupt lifetime/season totals.
- Existing beta.2 contracts continue functioning for servers that disable Hunter progression.

## Explicitly Out of Scope

- Location intel.
- Heat-generated wanted levels.
- Capture/jail mechanics.
- Team reputation.
- Cross-server leaderboards.
