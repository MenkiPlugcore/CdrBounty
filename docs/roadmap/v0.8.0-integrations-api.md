# CdrBounty v0.8.0 — Integrations & Public API

**Status:** Planned

## Goal

Turn CdrBounty into an extensible platform that other plugins can integrate with without depending on internal implementation classes.

## Public Java API

Planned entry point:

```java
CdrBountyAPI api = CdrBounty.getAPI();
```

Core API concepts should include:

- Read bounty state.
- Create supported contracts.
- Query active contracts.
- Query hunter profile/rank.
- Read Heat/wanted state.
- Read contract eligibility.
- Add/remove bounty through validated service methods.
- Register custom providers where supported.

The public API must never expose mutable internal persistence entities directly.

## Bukkit Events

Candidate public events:

- `BountyPlacedEvent`
- `BountyClaimedEvent`
- `ContractCreateEvent`
- `ContractAcceptEvent`
- `ContractCompleteEvent`
- `HunterRankChangeEvent`
- `IntelPurchaseEvent`
- `HeatChangeEvent`
- `WantedTierChangeEvent`
- `TargetCapturedEvent`
- `TargetEscapeEvent`

Each event must document:

- Whether it is cancellable.
- Whether it fires before or after persistence.
- Thread context.
- Whether modifying values is supported.
- Settlement implications.

## PlaceholderAPI

Planned placeholders may include:

- `%cdrbounty_bounty%`
- `%cdrbounty_heat%`
- `%cdrbounty_wanted_tier%`
- `%cdrbounty_hunter_rank%`
- `%cdrbounty_hunter_reputation%`
- `%cdrbounty_contracts_active%`
- `%cdrbounty_highest_bounty%`
- `%cdrbounty_is_wanted%`

Expensive placeholders require caching.

## Citizens

Optional integration:

- Bounty Master NPC opens bounty/contract GUI.
- Alive-contract delivery endpoint.
- NPC command traits/hooks where supported.

CdrBounty must start normally if Citizens is absent.

## WorldGuard

Optional integration:

- Disable placement/claim/tracking/capture in configured regions.
- Region-aware delivery points.
- Region policy resolution must fail closed for protected mechanics when explicitly configured.

## LuckPerms

CdrBounty should primarily use Bukkit permissions, while LuckPerms integration may provide:

- Context-aware checks where justified.
- Optional rank/meta display hooks.

Do not hard-depend on LuckPerms for normal permission operation.

## Vault

Refine Vault into provider abstraction for:

- Economy withdrawals/deposits.
- Capability/state reporting.
- Transaction failure handling.

CdrBounty should clearly disable money-dependent mechanics when no compatible economy provider is available rather than failing unpredictably.

## AuraSkills

Optional hooks may support:

- Reward provider for configured skill XP.
- Contract conditions based on server-defined integration capabilities.

Integration must use supported API surfaces and remain disabled cleanly when unavailable.

## Party / Guild / Faction Adapters

Create a generic relationship provider interface capable of expressing relationships such as:

- Same party.
- Same guild/faction.
- Allies/enemies where provider supports it.

Uses:

- Anti-collusion scoring.
- Team contract eligibility.
- Friendly-target protection.

No single third-party party/faction plugin should leak into core domain code.

## Discord / Webhook Hooks

Optional webhook notifications for:

- Legendary bounty creation.
- Public Enemy state.
- High-value claim.
- Season result.

Webhook calls must be asynchronous, rate-limited, and unable to block bounty settlement.

## Extension Interfaces

Potential provider interfaces:

- `RewardProvider`
- `RelationshipProvider`
- `TrackingPolicyProvider`
- `ContractConditionProvider`
- `BountySourceProvider`

Third-party extensions must have stable registration/unregistration rules and namespace identifiers.

## API Compatibility Policy

For `v0.8.x` and `v0.9.x`, the API is considered preview and may receive documented breaking changes.

The `v1.0.0` API surface will define the first stable compatibility contract.

## Acceptance Criteria

v0.8.0 is complete when:

- Public API exposes documented read/write operations without requiring internal classes.
- Public events have documented thread/cancellation semantics.
- PlaceholderAPI expansion is cached where necessary.
- Citizens and WorldGuard integrations work when present and disappear cleanly when absent.
- At least one relationship-provider integration can be implemented without modifying core contract code.
- Webhook failure cannot block or roll back a valid bounty claim.
- API misuse returns explicit failures/results instead of silent corruption.
- Example integration snippets are documented.

## Explicitly Out of Scope

- Cross-server consistency.
- Stable v1 API guarantee.
- Web dashboard.
- Redis-based messaging.
